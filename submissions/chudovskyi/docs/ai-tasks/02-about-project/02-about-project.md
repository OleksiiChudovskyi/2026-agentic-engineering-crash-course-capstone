Відтвори контекст за схемою broad → narrow → deep → verify і поверни один Markdown-документ українською (англійські терміни лишай англійською).
Markdown-документ підготуй за шаблоном YYYY-MM-DD_HH-MM_about-project.md та збережи у теці, поряд, де знаходиться цей файл.

Схема:

Broad — що це за продукт, які основні компоненти API (main app / routers / schemas / dependencies / middleware / settings), де точка входу, як структурована архітектура.
15–20 рядків.

Narrow — як установити залежності (pip install, requirements.txt чи pyproject.toml), запустити dev-сервер, запустити тести, і що з цього РЕАЛЬНО запускає CI (який workflow, який job, на якій ОС).
Таблиця: команда → що робить → хто запускає.

Deep — конфігурація логування: як проєкт вирішує рівні логування (DEBUG/INFO/WARNING/ERROR), де і як логується (консоль/файл), на кожній ОС чи в різних режимах;
Хто і коли написав рядок, що вирішує про логування, і навіщо (git log -L або blame + повідомлення коміту).

Verify — розділ «CLAUDE.md проти коду» (або інші доки, якщо є): 3–5 тверджень із документації, які ти звірив із кодом — збігається чи ні.
Розділ «Чого я не перевірив».

Правило: кожне твердження — з посиланням path:line або з командою, вивід якої його доводить. Не вгадуй: якщо не перевірив — пиши в розділ «Чого я не перевірив».
Без вступу і без висновків поза цими розділами.
