# About project — Prompt Manager API

Корінь репозиторію: `submissions/chudovskyi` (усі шляхи нижче — відносно нього). Окремого `CLAUDE.md` немає, тому для розділу Verify використано `README.md`.

## Broad

- **Продукт:** async REST API для керування особистими prompts; є окремий endpoint, що шле запит у Gemini і зберігає відповідь у БД (`README.md:3-7`, `app/api/v1/gemini.py`).
- **Стек:** FastAPI + SQLAlchemy 2 async (`asyncpg`) + PostgreSQL + Alembic + fastapi-users + fastapi-jsonapi + google-genai (`pyproject.toml:6-17`).
- **Точка входу (dev):** `app/main.py:6-13` викликає `uvicorn.run("server.server:app", host/port/workers/reload з settings.run)`.
- **Точка входу (ASGI app):** `app/server/server.py:42` — `app = create_app()`; prod стартує `gunicorn server.server:app --worker-class uvicorn.workers.UvicornWorker` (`compose.prod.yml:21-24`).
- **main app:** `create_app()` (`app/server/server.py:28-39`) створює `FastAPI(title/version/description з settings.project, lifespan)`, потім `_init_router` і `_init_builder`.
- **lifespan:** при старті `create_superuser_if_not_exists()`, при зупинці `db_helper.dispose()` (`app/server/server.py:21-25`).
- **routers:** `app/api/__init__.py:5-10` (prefix `/api`) → `app/api/v1/__init__.py:15-38` (prefix `/v1`) → підроутери `gemini`, `auth`, `users`, `messages`. Префікси беруться з `app/config/components/api_config.py:4-14`.
- **JSON:API ресурси:** prompts / categories / tags підключає `build_jsonapi_app(app)` з `app/api/v1/prompts.py:25` (через `_init_builder`, `app/server/server.py:15-18`), а не через `include_router`.
- **dependencies:** `app/api/v1/dependencies/` (`current_user.py`, `generic_view.py`, `http_bearer.py`); глобально на `/api/v1` навішено `Depends(get_http_bearer())` (`app/api/v1/__init__.py:15-18`).
- **auth:** `app/auth/` (backend, strategy, transport, user_manager, `users_fastapi.py`); `tokenUrl` = `settings.api.bearer_token_url` (`app/auth/transport.py:6`).
- **schemas / models / services:** `app/schemas/*` (Pydantic), `app/models/*` (SQLAlchemy: user, access_token, prompt, category, tag, prompt_tag), `app/services/*` (`gemini.py`, `users_db.py`, `access_tokens_db.py`).
- **settings:** `app/config/settings.py` — `pydantic-settings`, prefix `APP_CONFIG__`, nested delimiter `__`, env-файли `.env.template` + `.env.{ENV}` (`:35-45`); `ENV` береться з `APP_CONFIG__ENV`, default `dev` (`:31`). У prod додається джерело `/run/secrets` (`:74-82`).
- **middleware:** власного middleware немає — `grep -rniE "middleware" app` не знаходить жодного збігу (команда запускалась, вивід порожній).
- **DB:** `app/config/settings_db.py` (`db_helper`, engine з `settings.db.sqla.*`, `:47-50`); міграції `app/alembic/versions/` (8 файлів, 2026-03-25 … 2026-04-10).
- **Деплой:** три compose-файли `compose.dev.yml`, `compose.test.yml`, `compose.prod.yml` + `docker/Dockerfile.{dev,test,prod}`, `docker/entrypoint.*.sh`, nginx в `conf.d/nginx.conf`.
- **Entrypoint-скрипти** (dev/test) чекають Postgres через `nc -z`, роблять `alembic upgrade head`, сідять БД `app/fakedata/seed_db.py`, потім `exec "$@"` (`docker/entrypoint.test.sh:3-22`).
- **Тести:** `tests/` (pytest, `asyncio_mode = auto`, `pytest.ini:1-6`); дані й фікстури в `tests/fakedata`, `tests/fixtures`.

## Deep

**Що реально налаштовано.** Рівень і формат логування описує `LoggingConfig` — `log_level` (`debug|info|warning|error|critical`, default `info`), `log_format`, властивість `log_level_value` (`app/config/components/logging_config.py:6-23`); вона є полем `Settings.logging` (`app/config/settings.py:50`).

**Але ніде не застосовується.** `grep -rnE "log_level|log_format|basicConfig|dictConfig" app tests` знаходить лише самі визначення в `logging_config.py` і `settings.py:19,50`; викликів `logging.basicConfig`/`dictConfig` немає. Окремих `.env`-змінних `APP_CONFIG__LOGGING__*` у `.env.dev/.test/.prod/.template` теж немає (`grep -i log` по ним нічого не дає). Отже:

- Рівень і формат з `settings.logging` не впливають ні на що; реальний рівень root logger — Python default `WARNING`, а uvicorn/gunicorn налаштовують свої логери самі (це поведінка бібліотек, у репозиторії не перевірялась).
- Консоль/файл: файлових handler-ів у коді немає (`grep FileHandler` — порожньо); виводить у stderr/stdout процес.
- Логи застосунку: `log = logging.getLogger(__name__)` в `app/auth/user_manager.py:22`; події реєстрації/forgot-password/verify пишуться через `log.warning` (`:34,45,57,68`). Зверніть увагу: forgot/verify логи містять token (`:45-49`, `:57-61`) — прямий витік токенів у лог.
- Alembic окремо: `app/alembic/env.py:17-20` викликає `fileConfig(alembic.ini)`; `app/alembic.ini:115-143`: root `WARNING`, `alembic` `INFO`, `sqlalchemy.engine` `WARNING`, handler `StreamHandler(sys.stderr)`. Це видно в логу тестів: `INFO  [alembic.runtime.migration] ...` (`docs/ai-tasks/01-testing/2026-10-01_22-26_compose-test.log:149-152`).
- SQL echo: у `.env.dev` і `.env.test` стоїть `APP_CONFIG__DB__ECHO=1` (`.env.*:14`), але engine читає `settings.db.sqla.echo` (`settings_db.py:47`), тобто змінна мала б бути `APP_CONFIG__DB__SQLA__ECHO`. Доказ: у лозі тесту `grep -c "sqlalchemy.engine"` = 0, хоч ECHO=1. Тобто ця змінна фактично не працює.
- ОС/режими: різних налаштувань логування по ОС немає; режими dev/test/prod відрізняються лише env-файлами (`settings.py:31`), а в `LoggingConfig` від `ENV` нічого не залежить.

**Хто і коли написав і навіщо.** `git blame -L 6,23 app/config/components/logging_config.py` приписує всі рядки одному коміту `ef1d089` (автор Oleksii, 2026-10-01, повідомлення `01-start`); `git log -L6,23:...` показує лише цей коміт. Історія оригінального проєкту прибрана (README:54: «history of previous commits has been completely removed»), тому справжню дату й мотивацію рядка з `log_level` встановити неможливо — повідомлення коміту `01-start` нічого не пояснює. Мету можу лише припустити за кодом (підготувати конфіг під майбутнє `basicConfig`), це здогад, не факт.
