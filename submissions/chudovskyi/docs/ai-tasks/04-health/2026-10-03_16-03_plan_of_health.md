# План: 04-health — `GET /api/v1/health` (TDD)

## Контекст
Завдання `docs/ai-tasks/04-health/04-health.md`: публічний ендпоінт `GET /api/v1/health`, який повертає статус сервісу (`status: "ok"`), назву, версію та uptime.

Робота за TDD: спочатку тести, показати, що вони червоні, потім реалізація.

Критерій «готово» з завдання: зелені `uv run ruff check app`, `uv run ruff format --check app` і `docker build -f docker/Dockerfile.test`.

Заборонено: нові залежності, `pytest.ini`, `.github/workflows/`, `compose.*.yml`, `docker/`, `.env*`.

**Стан репо (перевірено):**
- Коміт `10-verification rollback` прибрав `app/services/health.py`, `tests/test_service_health.py` і `scripts/check.sh` із задачі 03. Усе пишу з нуля.
- `app/services/__init__.py` без `build_health`.
- `ProjectConfig` (`app/config/components/project_config.py`): `title="Prompt Manager"`, `version="1.0.0"`. У `pyproject.toml` стоїть `version = "0.1.0"`. Цю розбіжність лише фіксую у звіті, не виправляю.
- На хості немає `uv`, а pytest потребує Postgres. Тому ruff запускаю в зібраному тестовому образі, а pytest через `compose.test.yml` (як у задачі 03).

Дотримуюсь `.claude/rules/api-routes.md`, розділ A (plain `APIRouter`).

## Цикли (loop engineering)
Задача складається з двох вкладених циклів. Кожен має оракул, тобто об'єктивний сигнал, а також умову виходу, ліміт ітерацій і ескалацію.

| Цикл | Дія | Оракул (сигнал) | Вихід | Ліміт → ескалація |
|---|---|---|---|---|
| **R — red** (один прохід) | написати тести | pytest на 2 нових файлах | exit ≠ 0 **з очікуваної причини** (ImportError `app.services.health`, `404`) | якщо тести зелені або падають з іншої причини, отже тест хибний: виправляю тест, макс. 2 спроби, далі зупиняюсь і питаю |
| **G — green** (внутрішній) | мінімальна реалізація / правка | pytest на 2 нових файлах | exit 0, усі нові passed | 3 ітерації; на кожній читаю traceback і змінюю лише код у `app/`, а не тести. Після 3 зупиняюсь і показую останню помилку |
| **Q — quality gate** (зовнішній) | повний набір + ruff + build | `pytest` (усі), `ruff check`, `ruff format --check`, `docker build` | усі exit 0 | 2 ітерації; при регресії старих тестів повертаюсь у G. Тести не видаляю, правила ruff не вимикаю (AGENTS.md) |

**Правила циклу:**
- Сигнал беру лише з виводу команд, а не з власної оцінки. Кожен прогін — окремий лог у `docs/ai-tasks/04-health/` (`…_red.log`, `…_green-N.log`, `…_gate.log`).
- Тести в циклі G не змінюю: вони — специфікація. Виняток — явна помилка в самому тесті, і тоді я про неї кажу.
- Зовнішній стан прибираю після кожного прогону: `docker compose -f compose.test.yml down -v`.
- У звіті фіксую кількість ітерацій кожного циклу та що змінювалось між ними.

## Кроки

### 1. Тести (спочатку, «червоні»)
**`tests/test_service_health.py`** (чиста функція, без БД):
- `test_build_health_returns_ok_status`: `status == "ok"`, `service` і `version` повертаються як передані;
- `test_build_health_uptime_seconds`: `now = started_at + 90 s` дає `uptime_seconds == 90`;
- `test_build_health_negative_uptime_clamped_to_zero`: `now < started_at` дає `0`;
- `test_build_health_empty_name_raises`: `""` → `ValueError`;
- `test_build_health_blank_name_raises`: `"   "` → `ValueError`.

**`tests/test_router_health.py`**: клас з `@pytest.mark.asyncio`, фікстури `ac` і `api_prefix`, без `auth_headers`.
- `GET f"{api_prefix}/health"` повертає `200`;
- `status == "ok"`;
- `service == settings.project.title`;
- `version == settings.project.version`;
- `uptime_seconds` — `int` і `>= 0`;
- ключі відповіді рівно `{"status", "service", "version", "uptime_seconds"}`.

Тести 401 і 422 із розділу C правила тут не застосовні: ендпоінт публічний і без тіла. Це зазначу у звіті.

**Червоний прогін** (лог зберігаю як `…_red.log`):
`docker compose -f compose.test.yml run --rm --build api_test uv run pytest tests/test_service_health.py tests/test_router_health.py`
Очікування: service-тести падають на імпорті `app.services.health`, router-тест отримує `404`, exit ≠ 0. Потім `docker compose -f compose.test.yml down -v`.

### 2. Реалізація
- **`app/config/components/api_config.py`**: у `ApiV1PrefixConfig` додаю поле `health: str = "/health"`.
- **`app/schemas/health.py`** (новий): `HealthRead(BaseModel)` з полями `status: Literal["ok"]`, `service: str`, `version: str`, `uptime_seconds: int`. Експортую в `app/schemas/__init__.py`.
- **`app/services/health.py`** (новий): `build_health(service_name: str, version: str, started_at: datetime, now: datetime) -> dict`.
  - Чиста функція: без `datetime.now()` усередині, `now` обов'язковий.
  - Назва порожня або з самих пробілів → `ValueError`.
  - `uptime_seconds = max(int((now - started_at).total_seconds()), 0)`.
  - Експортую в `app/services/__init__.py`, як вимагає правило A.6.
- **`app/api/v1/health.py`** (новий):
  - `router = APIRouter(tags=["Health"])`;
  - на рівні модуля `STARTED_AT = datetime.now(timezone.utc)` — момент імпорту, тобто старту застосунку. Через `app.state` у lifespan не роблю, бо тести підміняють lifespan (`tests/fixtures/client.py`);
  - `@router.get("", response_model=HealthRead, status_code=status.HTTP_200_OK)`;
  - `async def get_health()` повертає `build_health(settings.project.title, settings.project.version, STARTED_AT, datetime.now(timezone.utc))`;
  - без `current_active_user`;
  - імпорти `from services import build_health`, `from schemas import HealthRead`, `from config import settings`.
- **`app/api/v1/__init__.py`**: `router.include_router(health_router, prefix=settings.api.v1.health)`. Шлях `""` разом із префіксом дає саме `/api/v1/health` без слеша в кінці.
- **`README.md`**: у розділ «📌 Basic API Endpoints (v1)» додаю підрозділ `### 🩺 Health` з рядком про `GET /api/v1/health` (публічний, без auth) і прикладом відповіді. Наявні неточності README не чіпаю.

### 3. Зелений прогін і «готово»
1. `docker compose -f compose.test.yml run --rm --build api_test uv run pytest` — увесь набір (очікую 40 + 6 нових = 46 passed). Лог зберігаю як `…_green.log`, потім виконую `down -v`.
2. `docker build -f docker/Dockerfile.test -t ipm_api:health-check .` → exit 0.
3. `docker run --rm --entrypoint uv ipm_api:health-check run ruff check app` → exit 0. Entrypoint перевизначаю, бо стандартний запускає міграції й чекає на БД.
4. `docker run --rm --entrypoint uv ipm_api:health-check run ruff format --check app` → exit 0.
5. Прибираю тимчасовий тег: `docker rmi ipm_api:health-check`.

Якщо `ruff format --check` знайде відхилення, виправляю вручну на хості (контейнер працює з копією коду) і повторюю кроки 2–4.
