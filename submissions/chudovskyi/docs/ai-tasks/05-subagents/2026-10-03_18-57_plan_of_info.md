# План: `041-info` через субагентів (orchestrator → workers A/B ‖ checker → join → test-runner → checker → людина)

## Context
`05-subagents.md` вимагає workflow із кількох субагентів у `.claude/agents/`: orchestrator, виконавець, рецензент/тестувальник, причому maker ≠ checker і з доказом рев'ю. Обрано варіант 2 з презентації (fan-out/join за DAG) на завданні `docs/ai-tasks/041-info/041-info.md`.
Рішення користувача:
- контракт `info` + `InfoRead` + `api_version`;
- коміти дозволені лише в окремій гілці `subagents/041-info` (і в гілках worktree workers), без push;
- gate включає compose-прогін тестів.

## Контракт C0 (власник — orchestrator)
- `ApiV1PrefixConfig.info: str = "/info"` (`app/config/components/api_config.py`).
- `app/schemas/info.py`: `InfoRead(BaseModel)`: `status: Literal["ok"]`, `service: str`, `version: str`, `api_version: str`, `uptime_seconds: float`; експорт у `schemas/__init__.py`.
- `app/services/info.py`: `STARTED_AT = time.monotonic()`; `build_info(service_name: str, version: str, api_version: str, started_at: float, now: float) -> dict` → **заглушка `raise NotImplementedError`**; експорт у `services/__init__.py`. Заглушка потрібна, щоб у B був імпорт, а червоний стан тестів був поведінковим, а не `ImportError` (слайди 22 і 43).
- Семантика (oracle для всіх): `api_version = settings.api.v1.prefix.strip("/")` → `"v1"`; `uptime_seconds = now - started_at`; порожня або пробільна `service_name` → `ValueError`; маршрут `GET /api/v1/info` (шлях `""`), публічний, `response_model=InfoRead`, `status_code=200`.

## DAG і власники файлів
```
S  (O) інфраструктура субагентів → commit → [людина: /agents або рестарт]
C0 (O) контракт + заглушка → commit
 ├─ A (worker, worktree): tests/test_service_info.py → commit "test"; потім app/services/info.py (реалізація) → commit "feat"
 ├─ B (worker, worktree): tests/test_router_info.py → commit "test"; потім app/api/v1/info.py → commit "feat"
 └─ K1 (checker, паралельно): контрприклади лише зі специфікації (без коду)
J-red (O): merge лише test-комітів A/B → C1 → test-runner → ЧЕРВОНИЙ (NotImplementedError, 404)
J-green (O): merge feat-комітів + підключення роутера в app/api/v1/__init__.py + README → C2 → ruff + test-runner → ЗЕЛЕНИЙ
K2 (checker): рев'ю diff C0..C2 + контрприклади K1 → findings; одна мутація (O застосовує, test-runner, git restore)
Людина: рішення про merge у main (поза цим планом)
```
Workers **не запускають** `uv`/pytest/docker: у worktree немає `.venv` (`uv run` спробує ставити пакети), а тести ділять одну БД (`setup_db` робить `drop_all`) і фіксовані container_name/порт у `compose.test.yml`. Тому всі прогони серіалізовані через test-runner на інтегрованому дереві.

## Файли кроку S (створює orchestrator до запуску субагентів)
- `.claude/agents/orchestrator.md`: `model: opus`; DAG, task brief (вимоги, base SHA, файли у власності, критерій готовності, stop condition, формат звіту зі слайду 61), join, gate, збереження доказів; для повторного використання через `claude --agent orchestrator`.
- `.claude/agents/worker.md`: `isolation: worktree`, `model: sonnet`, `maxTurns: 30`, `disallowedTools: Agent`. Працює лише за brief: спершу тест і commit, потім реалізація і commit. Звіт `Status / Base / Result SHA / Changed files / Commands / Gaps / Next action`. Хук `PreToolUse` (`Edit|Write`) → `python ${CLAUDE_PROJECT_DIR}/scripts/worker_guard.py`.
- `.claude/agents/checker.md`: `model: opus`, `tools: Read, Grep, Glob, Bash`, `disallowedTools: Edit, Write, NotebookEdit, Agent`. Bash лише для `git diff/log/show`. Повертає findings у форматі `expected / actual / severity / відтворення / artifact`; якщо знахідок немає, пише це прямо; окремо список «не перевірив».
- `.claude/agents/test-runner.md`: `model: haiku`, `tools: Bash, Read`. Процедура з `00-testing.md`: `docker compose -f compose.test.yml up --build --abort-on-container-exit --exit-code-from api_test > <log>`, потім завжди `down -v`. Повертає exit code, passed/failed, SHA і шлях до логу.
- `scripts/worker_guard.py` (stdlib, за зразком `protect_env.py`). Шлях рахує відносно `cwd` із JSON хука (у worktree `${CLAUDE_PROJECT_DIR}` вказує на основне дерево). Дозволяє лише `app/**` і `tests/**`. Блокує (exit 2) файли orchestrator: `app/config/**`, `app/schemas/**`, `app/*/__init__.py`, `README.md`, а також `.env*` і `sets/`. Перехресну власність A/B перевіряє O на join через `git diff --name-only` проти brief. Хук **не** кладу в `.claude/hooks/`, бо `CLAUDE.md` забороняє його редагувати.
- `.claude/settings.local.json` (глобально gitignored): `{"worktree": {"baseRef": "head"}}`. Без цього worktree субагентів створюються від `main` і не бачать C0. Закомічений `.claude/settings.json` не чіпаю.
- `.gitignore`: додати `.claude/worktrees/`.
- Commit S: `chore: add subagent definitions and worker guard hook` на гілці `subagents/041-info`.
- **Зупинка:** користувач виконує `/agents` (або перезапускає сесію), щоб нові агенти завантажились, і запускає Docker Desktop.
